- 2026-11-14 (real-app, core): MCP health probe is a minimal client written against the MCP 2025-06-18 transports (`crates/vision-core/src/mcp/probe.rs`), not `rmcp`. `rmcp` 3.10.0 is a stable release with child-process and Streamable HTTP client features, but it is async-only (tokio inside a blocking core), pulls in reqwest/hyper for HTTP, and its transports do not expose the per-message 1 MiB cap and process-group kill the spec requires (not verified in its source; would need wrapping anyway). The minimal client uses `ureq` 3 (blocking, rustls + platform verifier, redirects off so headers never go elsewhere, loopback bypasses proxies). Revisit when Vision runs its own MCP endpoint (§5.5).
- 2026-11-14 (real-app, core): Process groups: Unix uses std `CommandExt::process_group(0)` + `nix::sys::signal::killpg` (safe API); Windows uses `process-wrap` Job Objects. `process-wrap`'s Unix group `try_wait` loses the leader's exit status when a descendant outlives it, so it is not used on Unix.
- 2026-11-14 (real-app, core): Secrets via `keyring` 4 (`v1` feature: Keychain, Windows Credential Manager, Secret Service via zbus). `SecretString` has no `Serialize`, redacted `Debug`. MCP server names additionally may not start with `-` (stricter than spec) so they can never be parsed as `claude mcp` options.
- 2026-11-14 (real-app, core): IPC wire shapes: snake_case fields; `kind`-tagged unions for MCP transports and values (`{kind:"secret", has_value}`), `status`-tagged `ToolStatus`; `ToolView.status` is `null` until first check; `signed_in.account` may be `null`. TypeScript bindings generated by `ts-rs` 12 through `make bindings`; `make lint` runs `bindings-check`.
